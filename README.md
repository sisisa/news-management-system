# news-management-system(ニュース管理システム)
news-management-systemは、ニュース情報の登録・編集・削除や検索、公開状態の管理を行うWebアプリケーションです。
今回はVue.jsのComposition APIを採用して開発しております。

## 実装した機能一覧
* **ニュース一覧**: 登録済みニュースを一覧表示
    * `components/NewsList.vue`が対象
* **ニュース詳細確認**: 選択したニュースの詳細を表示
    * `components/NewsDetailManager.vue`が対象(ステータスによって詳細確認・編集を切り替えている)
* **ニュース新規追加**: ニュース情報を新しく作成可能
    * `components/NewsForm.vue`が対象
    * id は「現在の最大 id + 1」で採番している
* **ニュース編集**: ニュース情報を編集して、データを更新可能
    * `components/NewsDetailManager.vue`が対象(ステータスによって詳細確認・編集を切り替えている)
    * 編集時もフォームコンポーネント：`components/NewsForm.vue`を使用して情報を編集している
* **ニュース削除**: ニュース情報を削除
    * `components/NewsDetailManager.vue`が対象(このコンポーネント内の削除ボタンをクリックして削除可能)
    * IDを指定してデータを削除している
* **キーワード検索**: キーワードに一致するニュースを検索
* **カテゴリ検索**: カテゴリごとにニュースを検索
* **公開状態の管理**: ニュースごとに公開・非公開を設定
* **入力チェック**: 必須項目が入力されていることを確認
    * el-formのruleを用いて必須項目が入力されているか確認、入力されていなかったらデータを登録出来ないようにしている

## 開始手順
### 1. **リポジトリをクローン**
```bash
git clone https://github.com/<your-account>/news-management-system.git
cd news-management-system
```

### 2. **Vue.jsの開発環境を構築**
Vue.jsのプロジェクト作成方法やパッケージマネージャーは、開発開始時に決定します。
そして、今回はパッケージマネージャー：bunを参考にして手順を記載していきます。

### 3. **開発サーバーを起動**
コマンドプロンプト・ターミナルにて以下の2つのコマンドを実行することでこのアプリケーションの開発をすることが出来ます。

**開発用のサーバー起動：**
```code
bun run dev
```

**サーバーサイド起動(API通信をするために必要)：**
```code
bun run server
```

## データ形式
データは`public/news_sample.json`のJSONファイルを対象としてデータの呼び出し・書き込みをしています。

### JSON内のデータ構造
```json
[
  {
    "id": "1",
    "title": "システムメンテナンスのお知らせ",
    "category": "お知らせ",
    "body": "メンテナンスの実施予定についてお知らせします。",
    "publishDate": "2026-10-09",
    "isPublished": "公開"
  }
]
```

* `id`: ニュースを識別する一意のID
* `title`: タイトル
* `category`: カテゴリ
* `body`: 本文
* `publishDate`: 公開日（`YYYY-MM-DD` 形式）
* `isPublished`: 公開状態（公開・非公開の文字列で管理）

## 現段階で実装出来ていない箇所・懸念点

### ①公開/非公開の適用
**ステータス：未実装**

データとして、公開/非公開の設定は出来るようにしている。
だが、非公開にしても実際にデータが隠される事はなく、どの段階・条件で公開/非公開を適用すれば良いのか現状不明瞭である。

### ②`NewsDetailManager.vue`を分割して`NewsForm.vue`(フォームコンポーネント)は新規登録用のコンポーネントに適用するべきか？
**ステータス：懸念点**

前提として、各機能の実装は出来ており、データの新規登録から削除まで出来るようになっている。
だが、長期的な運用・機能の改修を想定した際に既存の構造だと以下のようにどこに何があるのかが分かりづらくなっているため、コンポーネントを独立OR分割した方が良いかもしれないと考えている。

* `NewsDetailManager.vue`→編集・詳細確認・削除機能(詳細確認は`NewsForm.vue`(フォームコンポーネント)使用)
* `NewsForm.vue`単体→新規登録機能(新規登録をしている箇所を探せと言われたら名前的に見つけるのが難しそうと感じている)
